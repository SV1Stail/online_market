# E2E-тесты бэкенда

Тесты поднимают gRPC-сервер внутри процесса через `bufconn` и вызывают его
только через сгенерированные protobuf-клиенты. В цепочку сервера включены
рабочие промежуточные обработчики, транспортный слой и бизнес-сервисы.

HTTP/JSON gateway живёт в отдельном репозитории `online_market_gateway`; его
unit-тесты и проверки middleware находятся там. Здесь остаются gRPC E2E на
моках без зависимости от gateway-процесса.

PostgreSQL, Redis, генераторы идентификаторов и определение IP заменены
детерминированными реализациями в памяти. Это позволяет проверять MVP-сценарий
без внешних сервисов и соответствует принятому в проекте подходу к E2E-тестам
на моках.

Основной сценарий `TestMVPFlow` проверяет:

- получение доступных товаров из публичного каталога;
- создание корзины и добавление товара;
- оформление заказа и повтор запроса с тем же ключом идемпотентности;
- получение заказа покупателем по номеру и токену;
- запрет административного API без токена доступа;
- вход администратора, просмотр заказа, смену названия и статуса;
- создание категории и товара, изменение цены и архивацию товара;
- скрытие архивного товара из публичного каталога.

Сценарий `TestAdminSessionLifecycle` проверяет ротацию токена обновления, запрет
повторного использования старого токена и отзыв сессии при выходе.

Запуск из корня репозитория:

```bash
make backend-test-e2e
```

Запуск из каталога `backend`:

```bash
make test-e2e
```

Эти тесты не проверяют SQL-запросы, миграции, Lua-логику Redis и сетевое
взаимодействие с внешними каналами уведомлений. Для этого нужен отдельный набор
интеграционных тестов с инфраструктурой в Docker Compose.
